# 演示脚本（彩排清单）

> **用途**：演示当天照着走；同时也是「稳定性」的判据 —— 每次改动后手点一遍，**任何一步"没反应"就先修它**。
> **配套**：能自动化的步骤都有对应验证，跑 `cd desktop && npm run verify:demo`（见文末对照表）。
> **目标时长**：≤ 8 分钟（含讲解）。每步都标了耗时基准，超太多说明那步不稳。

---

## 0. 前置条件（**演示前必须逐项确认**）

演示翻车几乎都是这里没满足，不是代码坏了。

| 项 | 谁需要 | 怎么确认 | 不满足会怎样 |
|---|---|---|---|
| **模型额度** | AI Agent 标签 | 打开 AI Agent，发一句"你好" | 回复报 **429 限流**（免费额度很容易撞） |
| **网络** | AI Agent | 同上 | 同上 |
| **PostgreSQL + Redis** | 后端面板 / `demo` / `notes` / `conduit` | 跑那些入口前先起（`README` 有说明） | 点运行后**一片沉默**（它在等连接） |
| **moon 工具链** | 打开 MoonBit 项目 | `moon version` | 文件树/诊断/LSP 都空 |
| **Node/npm** | 打开 Node 项目 | `npm -v` | 运行报 `spawn npm ENOENT`（已修，但 PATH 得对） |

> **省事的做法**：演示只走**零依赖**路径（`hello` 示例 + 项目中转站），把 PG/Redis 那一摊留给"问答环节"讲，不放现场。

## 4. 运行项目 —— **看到运行效果**（基准 30 秒）★ 最重要的一步

| 步骤 | 操作 | 期望看到 | 没反应先查 |
|---|---|---|---|
| 4.1 | 点「运行项目」 | 弹出入口列表，**中文标题 + 命令小字** | 项目类型识别（unknown → 看提示里的目录对不对） |

> **这一步是"完整 IDE"的验收点**：从"点运行"到"看到界面"必须在 5 秒内闭环。

## 对照表：哪一步能自动验

| 步骤 | 自动验证 | 说明 |
|---|---|---|
| 1.2 / 1.3 | `verify-welcome.js` | 标签数、无项目态落地 |
| 4.1 / 4.2 / 4.3 | `verify-run-url.js` | 真跑 hello、抓 URL、fetch 页面 |
| 4.5 | `test-runner-detect.js` | 项目类型识别（纯 Node） |
| 5.1 ~ 5.5 | `verify-relay.js` | 中转站全流程（42 项） |
| 6.2 / 6.3 | `verify-agent-config.js` | 配置弹窗（真点击） |
| 2 / 3.5 / 3.6 / 7 / 8 | `e2e-features.js` | 23 项功能体检 |
| **3.3 / 3.4 / 6.4 / 6.5 / 7.2** | ❌ **只能靠手点** | 依赖 LSP/网络/外部服务，脚本验不了 |

**结论**：**8 个步骤里，5 步能自动验、1 步必须手点**（3.3/3.4 的 LSP、6.4/6.5 的 AI 回复、7.2 的后端）。

**所以彩排流程是**：
```bash
cd desktop && npm run verify:demo     # 自动部分（约 2 分钟）
# 然后手点：3.3 / 3.4 / 6.4 / 6.5 / 7.2 —— 这 5 处是脚本覆盖不到的
```

**手点这几处时，只要有一次"怎么没反应"，就先修它，再谈新功能。**
