# PH3-SEC-04～09：在**真实路径上**复核安全边界

- 日期：2026-09-26
- 新增：`test-agent-security-boundaries.js`（**55/0**），已挂 CI
- 全程用临时 workspace + 临时用户目录，结束时清理

## 为什么要单独做这一批

这些约束"代码里写着"已经很久了 —— 但**写着 ≠ 成立**。所以每一条都**真调一次** API，
并断言**副作用**（文件有没有被改），而不是只看返回值的形状。

## ★ 复核的最主要发现：这里是**两套机制**，不是一套

| 机制 | 覆盖什么 | 怎么生效 |
|---|---|---|
| **危险路径表** `DANGEROUS_PATH_RE` | `.git/` / `.env` / `.npmrc` / `.netrc` / `id_rsa` / `id_ed25519` / `credentials` / `.aws` / `*.pem|key|pfx|p12` | **无论有没有确认都拒** |
| **用户确认闸** `deps.confirm` | **其余全部**（含 `.moonbit-work/agent-rules.md` 这类规则文件） | **没有 confirm 回调 → `not-confirmed` 直接拒** |
| **路径沙箱** `resolveInsideWorkspace` | workspace 之外的一切 | 先于上面两者 |

我第一版把 `agent-rules.md` 塞进了"危险文件"列表里测 —— 得到"它被改了"的**错误结论**。
实际上它**不在**危险表里，它靠的是**确认闸**。**两套机制混在一起测，会得出相反结论。**

## 逐条结论

- **SEC-09 路径沙箱**：`../` / `..\` / `/etc/passwd` / `C:/Windows/...` 全拒；
  **前缀相近的兄弟目录**（`WS + '-evil'`）也拒；workspace 根本身被认成破坏性目标。
- **SEC-04 Patch 只能 workspace 内**：workspace 外的 patch 被拒，且**文件根本没被创建**。
- **SEC-05 危险文件**：`.env` / `id_rsa` / `cert.pem` / `.git/config` 逐个拒，
  并断言**内容一个字节都没变**。
- **SEC-06 规则文件**：**没有用户确认 → `not-confirmed` 拒**，且**给出预览**；
  普通源码在未确认下也拒（**同一道闸，不搞特殊**）。
  **但确认之后应当能改** —— 清单说的是"不能**无确认**改"，不是"永远不能改"。
- **SEC-07/08 Provider Key**：`providers.json` 在**用户目录**（即 workspace 之外）→
  改它被路径沙箱拦、读它也被拦，且**返回值与错误信息里都不含 Key**（用相对路径穿越也一样）。
- **边界复核**：workspace 内的普通文件**能**读能改（否则沙箱就成了"什么都不让做"）；
  **没打开项目时拒绝而不是回退到某个目录**。

> 最后一条尤其重要：一个"什么都拒绝"的沙箱看起来最安全，但它是坏的 ——
> 用户会发现功能不可用，然后去关掉它。**能拒绝该拒绝的，也能放行该放行的**，才叫边界成立。
