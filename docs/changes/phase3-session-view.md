# PH3-SESSION-01～10：会话可用性层（标题 / 搜索 / 导出 / 回放）

- 日期：2026-09-26
- 新增：`desktop/session-view.js` + `test-session-view.js`（**76/0**），已挂 CI

## 边界

原有 `session.js` 管**存储与不可变**（messages/toolCalls/patches/verifications，都带上限）。
这一层只做"给人看与给人查"，**不改旧层**（RHLE-04 渐进）。

## ★ SESSION-10 是这批的重点：回放**白名单取字段**

清单要求"只展示 任务/动作/工具/结果，**不展示隐藏思维链**"。

做法不是在文档里写一句，而是**结构保证**：`replaySession` **白名单取四类字段**，
而不是"把 session 丢出去 JSON 化"。因为后者的下场是迟早有一天——
模型响应里的 `reasoning` / `thinking` / 内部草稿会顺着导出与界面漏出来。

测试里专门造了一个**带 `reasoning` 与 `thinking` 的 assistant 消息**，断言：
1. 产出里**没有**这些字段名；
2. **内容里也不含**那段思维链文本（防"换个字段名照样漏"）；
3. 导出（JSON 与 Markdown）走的是**回放的白名单结果**，不是原始 session；
4. 工具只给**结论摘要**，不给参数全文（参数里可能有敏感内容）。

## 其余各项

| 项 | 做法 |
|---|---|
| 01 标题 | 取**第一条 user** 消息；截断带省略号；没有任务就明确"（未命名会话）"，**不拿时间戳假装标题** |
| 02 列表 | 标题/项目/状态/四类计数；按更新时间倒序；默认不含归档 |
| 03 搜索 | 匹配标题与消息，并**说明命中在哪**（界面可高亮） |
| 04 Resume | 只接**同一工作空间**里最近更新的非归档会话（不跨项目） |
| 05/06 归档/删除 | 删除必须 `confirmed: true`，并留墓碑 |
| 07 导出 | JSON 给机器、Markdown 给人，两者都不含思维链 |
| 08/09 关联 | `withLinks` 在**记录时**写入 `sessionId`/`taskId`（事后靠时间猜，多任务并行时必然错） |
