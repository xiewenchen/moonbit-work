## P20-07/08：恢复要分"正常退出"和"崩过"

同一份快照，两种收场：

| 情况 | 怎么判 | 恢复什么 |
|---|---|---|
| 首次启动 | 没有快照 | 什么都不恢复 |
| 上次**正常退出** | `running=false`（退出时清掉了标记） | **完整恢复**：项目 + 标签 + 当前文件 |
| 上次**异常退出** | 启动时 `running` 还是 `true` | ★ **只恢复项目**，标签与当前文件丢掉 |

第三种是这段代码唯一真正重要的地方：**崩过一次就不要把现场原样搬回来**。
否则用户下次打开会看到一堆"当时打开的标签"，而它们未必是他现在想处理的 ——
更糟的是，崩溃可能与其中某个文件有关。所以降级并**说明原因**：

> 上次没有正常退出（可能是崩溃或被强制结束）。只恢复项目，不恢复打开的标签与文件
> —— 免得把不确定的现场再搬回来。

实现上就靠一个标记：启动时 `markRunning()`，正常退出时 `markCleanExit()`。
**这一步不做，就会被判成异常退出**（测试里也盯着"更新位置不会误清 running 标记"）。

另外快照**只记"位置"不记"内容"**（项目路径/标签/当前文件），测试断言快照里
搜不到文件正文 —— 恢复现场不等于把代码抄一份。

## P20-09：环境检查只报事实，且"没装"≠"探测报错"

检查 MoonBit / Node / Git / Docker / Agent 五项，每项都带：

- **为什么需要它**（`why`）—— 比如 Docker 那条写的是"后端的 PostgreSQL / Redis 依赖"；
- **缺了怎么办**（`hint`）—— 是可执行建议，不是"环境异常"这种废话：
  "装 Docker Desktop；没有它后端一键跑不起来（**但不影响读代码**）"。

两处刻意区分：

1. **`found:false` 与 `error` 分开**：探测函数**抛异常**（比如超时）不等于"没装"。
   摘要会说清："另有 N 项探测时报了错（与'没装'不是一回事）"。
2. **没注入探测能力就明确抛**，而不是静默返回"全好" —— 后者会让环境检查变成摆设。
