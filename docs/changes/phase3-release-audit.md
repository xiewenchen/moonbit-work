# PH3-REL-01～09：发布前工程治理审计

- 日期：2026-09-26
- 工具：`tools/audit-release.js`（`--json` / `--ci`）+ 基线 `tools/release-baseline.json`
- 现状：**79 个模块，真缺口 9 个（新增 0）**

## ★ 这一类审计最容易做错的地方：**分类**

不能简单地"没有 `test-*.js` 就报缺口"。本仓库里：

| 类别 | 判据 | 是否要求单测 |
|---|---|---|
| `*-main.js` | 接线层（IPC/handler） | **不要求** —— 由 `verify-*` 覆盖 |
| `main.js`/`preload.js`/`renderer.js` | 应用外壳 | **不要求** —— 由 Electron verify 覆盖 |
| `e2e-*`/`probe-*`/`inspect-*`/`export-*` | 工具脚本 | **不要求** |
| 其余 | 纯逻辑 | **要求** |

## 第二处关键判据：**"没有同名测试文件" ≠ "没被测"**

第一版把 `mock-llm.js` 报成新缺口 —— 但 `test-agent-adapter.js` 直接 `require` 了它并断言了行为，
那是**真覆盖**。所以加了 `referencedByTest`：被任何测试 `require` 过就算有覆盖。
修完之后新增缺口从 1 变成 **0**。

> 这两处都是"判据错 → 报假缺口"。假缺口与假绿一样有害：**它会让人开始不信这个工具**。

## 双向自测

- 加一个**没有测试**的新纯逻辑模块 → `--ci` **exit 1**，并精确报出模块名；
- 给它**加上测试** → `--ci` **exit 0**（正例不误报）；
- 还原 → exit 0。

（自测第一次用 `probe-untested.js` 当探针名，结果撞上了 `probe-*` 排除规则 ——
**探针名字本身也是被测对象的一部分**，与上次"探针插在表外"是同一类。）
