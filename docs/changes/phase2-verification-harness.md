# 验证器自身的加固：给"度量"写测试（P19）

- 任务：P19「测试体系」中的验证器加固
- 日期：2026-09-24
- 状态：PASS（元测试 36/0；全量 26 个纯 Node 测试无红灯）

## 起因

上一轮写 P12 验证时，审计出 **25 处 `chk('x', [a,b], [c,d])`** —— `chk` 是布尔语义、
**数组恒为真**，那些断言**从来没有生效过**。我此前报告的若干"N/0"里因此混着假的。

结论很直接：**测试脚本自己没被测试过**。这一轮就补这一课。

## 做了什么

### ① 抽公共断言工具 `verify-harness.js`

原来每个 `verify-*.js` 都自己写一份 `chk` —— **16 份定义、三种写法**，其中一批是裸布尔。
新模块只提供两种断言，并且**用错会被当场抓住**：

```js
chk(name, ok, detail)   // 布尔断言；ok 不是布尔 → 立刻失败并提示用 eq
eq(name, got, want)     // 深比较；数组/对象必须用这个
```

两处刻意的设计：
- **类型闸**：`typeof ok !== 'boolean'` 直接判失败。这正是当初"数组静默通过"的位置。
- **深比较键序无关**：原来用 `JSON.stringify` 比较，对 `{a:1,b:2}` 与 `{b:2,a:1}` 会判**不等** ——
  一个隐藏的假失败来源。

### ② 给验证器写测试 `test-verify-harness.js`（36 项，已挂 CI）

关键是**不用被测对象来自证** —— 用独立计数器，逐条确认"能抓到错"：

| 分组 | 内容 |
|---|---|
| ① | **传数组/对象/字符串/数字/null/undefined 当条件 → 必须失败**（第一节就是这个） |
| ② | `chk` 的正常用法（真/假/表达式/失败时输出说明） |
| ③ | `eq` 的正常用法（含 `null` vs `undefined`、`false` vs `0` 不等） |
| ④ | 深比较键序无关；**对照**：`JSON.stringify` 键序敏感（所以不能用它做相等） |
| ⑤ | 计数器 / `summary` / `exitCode` / `failures` 是副本 |
| ⑥ | 正例全部通过（不误报） |

### ③ 给 9 个裸布尔 `chk` 补上同一道闸

先查了它们**有没有实际踩坑** —— 结果 `数组当条件` 的调用数**全是 0**：
也就是说实际假通过只在那 7 个已修的脚本里，这 9 个只是**缺防护**。仍然补上，防复发。

## 顺带发现并修的 **4 个长期红灯**

跑全量纯 Node 测试时才发现（都**不在 CI 里**，所以一直没人知道）：

| 脚本 | 现象 | 真因 | 处理 |
|---|---|---|---|
| `test-backend.js` | 7/19 | 需要 Docker 容器 `mbp-pg`/`mbp-redis` + native 二进制 | 环境不满足 → **明确 SKIP**（打印原因，exit 0） |
| `test-api-debug.js` | 7/17 | 需要后端在 `:8110`，10 项全是 `ECONNREFUSED` | 同上（它**自己已经识别**了 refused，只是退出码仍报 1） |
| `test-lsp-e2e.js` | 1 失败 | 断言"零诊断"，实际有 32 条 `test_unqualified_package` **warning** | 断言改为"**无 error**（warning 允许）" |
| `test-term.js` | 崩溃 | 用 `node` 跑 Electron 脚本 → `require('electron')` 返回路径字符串 | 加守卫 + 打印正确用法 |

**四个的共同点**：都不在 CI 里 → 长期红着、无人知晓。
**共同处理原则**：**环境/运行方式不适用时明确 SKIP，而不是刷一屏 FAIL** ——
因为"每次都是红的测试"等于**没有测试**，而且会训练人忽略输出。

## 一个操作事故（记下来）

这一轮**两次**批量替换翻车：

1. 正则里多写了一对捕获括号 → `m.group(2)` 拿到整段原文 → 把 2 个文件写坏；
2. （上一轮）python 普通字符串里的 `\n` 变成真换行 → 30 个文件写坏。

**两次都是被全量 `node --check` 当场抓到的**。教训：**批量改源码必须
① 先 dry-run 打印命中情况，② 改完全量语法检查**。后来改成"精确字符串替换（不用正则）"
并先打印计划，就一次通过了。

  等于这部分能力在 CI 里是**无覆盖**的 —— 这是既有事实，本次只是让本地不再误导。
