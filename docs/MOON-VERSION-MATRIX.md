# MoonBit 版本矩阵（PH3-MB）

> 这份文档回答一个问题：**`warnings = "-79"` 到底能不能收窄？**
> 结论：**现在不能** —— 而且原因是可以验证的，不是"感觉有风险"。

建立日期：2026-09-26

---

## 一、实测：`-79` 出现在 **10 个包**（资料里写的是 3 个）

```bash
grep -rln "\-79" --include="moon.pkg" . | grep -v "_build\|\.mooncakes"
```

| 包 |
|---|
| `app/` `bench/` `conduit/` `demo/` `http/` `http/server/` |
| `kernel/` `pg/` `pg/client/` `redis/` |

**共 10 个。** 此前资料说"只涉及 3 个包"—— 那是**不准的**。这条先把数字订正掉：
**要动就是动 10 个包，不是 3 个。**

（对照：`-29` 出现在 **21 个包**。它是 `test_unqualified_package`，
即"测试里隐式导入了包内符号"——与 `-79` 是两回事，别一起处理。）

---

## 二、`-79` 的原因：**本机无法验证**（这是关键）

按 PH3-MB-05「不要在坏的本机环境强行判断」，做了一个**可复现的对照**：

```bash
cd conduit
sed -i 's/-29-79/-29/' moon.pkg        # 把 -79 去掉
moon check --target native
```

结果：

```
Finished. moon: ran 2 tasks, now up to date (33 warnings, 0 errors)
```

**告警数一个没变（还是 33），一个 error 都没出。**

> 这说明：**本机这份工具链根本不会产生 `-79` 对应的告警。**
> 于是"去掉它会不会有问题"在本机**从原理上就测不出来** ——
> 删掉它不会报错，不是因为安全，而是因为**本机看不到那个检查**。

`-79` 是**跨版本兼容性**相关的告警编号。屏蔽它的含义是：
「在一个**更新**的工具链上，某处写法会被告警，而本机这份旧工具链不会」。
既然本机不告警，**两件事都成立得毫无差别** —— 这种"无差别"不构成任何证据。

## 三、版本矩阵

| 环境 | moon 版本 | 能否看到 `-79` | 用途 |
|---|---|---|---|
| **本机** | `0.1.20260920 (914d7da 2026-09-20)` | **否**（实测：去掉 `-79` 后告警数不变） | 日常开发、跑非 MoonBit 的测试 |
| **CI** | 由 `curl .../install/unix.sh \| bash` 装 **当前最新** | **可能**（取决于装到哪一版） | **唯一**可用来判断 `-79` 的环境 |
| 旧工具链 | 与本项目最初开发时相近 | 否 | 只作参考，不作为判据 |

CI 里已经有一行 `moon version`（`.github/workflows/ci.yml`），
所以**每次 CI 跑完都能知道用的是哪一版** —— 这正是这一节要的可追溯性。

## 四、结论与处置（PH3-MB-06）

**不收窄。** 理由不是"怕出问题"，而是：

1. 本机**看不到** `-79` → **无法证明**收窄安全（第二节的对照已证）；
2. 收窄要动 **10 个包**（不是 3 个），影响面比资料描述的大；
3. 清单明确要求：**「只有版本矩阵证明安全才收窄」** —— 而目前矩阵**还没有**证明。

**因此这一项的正确状态是 `DEFERRED`（等证据），不是 `TODO`（等动手）。**

### 什么条件下可以收窄

需要**同时**满足：

1. CI（或某个明确版本的 moon）里，去掉 `-79` 后**不产生新增告警**；
2. 该版本是**本项目要支持的版本**（写进上表）；
3. 收窄按 RULE-04 **逐个包**做（一次一个，每个都跑 CI），而不是 10 个包一起改。

在满足之前，`warnings = "-29-79"` **保持不变** —— 它是**跨版本兼容措施**，不是技术债。

## 五、为什么这份文档本身就属于 PH3-MB

清单把这几条列为"任务"（MB-01～06），但它们的产出**不是代码改动**，而是：

- **一个订正过的数字**（10 个包，不是 3 个）；
- **一次可复现的对照实验**（证明本机看不到 `-79`）；
- **一条明确的判据**（什么条件下才允许收窄）。

把这些写下来，比"改 10 个 `moon.pkg` 然后 CI 变红"有用得多 ——
后者会让人以为"MoonBit 那边有问题"，而真正的问题是**本机工具链版本不够新**。
