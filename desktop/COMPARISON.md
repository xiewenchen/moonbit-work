# 我们的 IDE vs VS Code —— 对比与差距分析

> 目的：用 VS Code 当参照物，找出「后端一站式平台」的桌面壳还差什么，据此排优先级。

## 1. 架构对比

| 维度 | VS Code | 我们（`desktop/`） |
|---|---|---|
| 外壳 | Electron | Electron（同） |
| 编辑器内核 | Monaco | Monaco（同） |
| 进程模型 | 主进程 + 渲染进程 + **扩展宿主进程** + **语言服务器进程** | 主进程 + 渲染进程（单窗口） |
| 能力扩展 | **Extension API**（几万个扩展、市场） | 无扩展系统；能力写死在 `main.js` |
| 通信 | 主↔渲染 IPC；与扩展/语言服务走 **RPC / LSP / DAP** | 主↔渲染 `ipcMain`/`contextBridge` |
| 构建/运行 | 终端 + 任务系统（tasks.json） | 工具栏按钮 → 主进程 `spawn moon` |
| 智能提示 | LSP（补全/跳转/诊断） | 无（Monaco 只用 `rust` 语法近似） |

**结论**：底层选型一致（Electron + Monaco）；差距在**上层**——文件管理、多标签、命令面板、终端、LSP、扩展点。

## 2. 能力矩阵

| 能力 | VS Code | 我们 | 差距 |
|---|---|---|---|
| 文件资源管理器（树） | ✅ | ❌ | **大** |
| 多标签编辑器 | ✅ | ❌（单编辑器） | **大** |
| 打开/保存文件 | ✅ | ❌（只有静态示例文本） | **大** |
| 命令面板 `Ctrl+Shift+P` | ✅ | ❌ | **大** |
| 集成终端 | ✅ | 半（按钮跑固定命令） | 中 |
| 问题/输出面板 | ✅ | 半（仅输出） | 小 |
| 状态栏 | ✅ | ❌ | 小 |
| 搜索 / 替换 | ✅ | 仅 Monaco 内置 | 小 |
| Git 集成 | ✅ | ❌ | 中（可后置） |
| 扩展系统 | ✅ | ❌ | 大（长期） |
| LSP 智能提示 | ✅ | ❌ | **大**（我们有 `moon ide` 可接） |
| 调试（DAP） | ✅ | ❌ | 中 |
| 设置 / 主题 | ✅ | ❌（固定 vs-dark） | 小 |
| 快捷键 | ✅ | ❌ | 小 |

## 3. 我们的**差异化**（VS Code 没有的）

VS Code 是**通用**编辑器；我们的优势是**内置 MoonBit 后端兼容层**：

- 一键起 `notes`/`demo` 服务、看状态（不用手敲 `moon run`）
- 直接连 PostgreSQL / Redis 看数据（我们已经写好了两个客户端）
- 平台内核（`kernel/`）：认识模块、驱动 `moon`、消费 `moon ide`

**方向**：先把「通用编辑器该有的」补齐到能用，再把「后端一键化」做成 VS Code 做不了的事。

9. 搜索（跨文件）

### P2（更远）
